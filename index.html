01 — What it is

SGLang

A high-performance, open-source serving framework for large language and multimodal models. It runs inference with low latency and high throughput — from one GPU to large distributed clusters.

SGLang is a serving framework: requests enter the runtime, it schedules them across one GPU or a whole cluster.

02 — The language

SGL

Structured Generation Language — a small language embedded in Python for writing multi-step model programs: parallel and forked generations, branching, and JSON- or regex-constrained decoding. One optimizable program instead of isolated API calls.

SGL expresses forks, parallel generations and output constraints in one program, so the runtime can see and optimize the whole structure.

03 — Co-design

Co-designed

Frontend and backend were built together. Language primitives expose program structure — shared prefixes, forks, constraints — and the runtime exploits that structure for batching and cache reuse. A generic HTTP API hides exactly this.

Structure flows from the language down to the runtime; optimizations flow back as speed. The two sides were designed as one loop.

04 — KV cache reuse

RadixAttention

KV caches live in a radix tree keyed by token sequences. Every new request reuses its longest matching prefix — a shared system prompt, few-shot examples — and computes only the unmatched suffix. Sharing is automatic; LRU eviction frees memory.

The tree keys every sequence by its tokens. A new request matches the longest shared prefix for free and only pays for its own suffix.

05 — Scheduling

Zero-overhead CPU scheduler

The CPU prepares the next batch while the GPU runs the current one. Scheduling and kernel execution overlap, so there are no idle gaps — kernels launch back-to-back and the GPU stays saturated.

CPU decisions for the next batch are made during the current GPU batch, so the two never serialize and the GPU timeline is fully tiled.

06 — Batching

Continuous batching

The batch is rebuilt on every token step. A new request joins immediately, a finished one leaves instantly. Nothing waits for the slowest request in a fixed batch, which lifts throughput and cuts latency together.

Each token step is a fresh scheduling point: R3 and R4 join mid-flight, R1 and R2 leave the instant they finish.

07 — Disaggregation

Prefill / decode split

Prefill is compute-bound; decode is memory-bound. Run them on separate workers: prefill nodes process prompts, ship the KV cache over RDMA, and decode nodes stream tokens. Each pool scales on its own.

Different bottlenecks live on different machines. Prefill ships KV, decode streams tokens, and the two pools scale independently.
Y compose.yaml YAML▾ 
services:
  model-download:
    image: lmsysorg/sglang:latest-cu130
    container_name: model-download
    environment:
      - HF_ENDPOINT=https://hf-mirror.com
    volumes:
      - hf-cache:/root/.cache/huggingface
    entrypoint:
      - python3
      - -c
      - |
        import time
        from huggingface_hub import snapshot_download, try_to_load_from_cache
        model = "Qwen/Qwen3-0.6B"
        if try_to_load_from_cache(model, "config.json") is not None:
            print(f"Model already downloaded: {model}", flush=True)
        else:
            while True:
                try:
                    snapshot_download(repo_id=model)
                    print(f"Download complete: {model}", flush=True)
                    break
                except Exception as e:
                    print(f"Download failed, retrying... ({e})", flush=True)
                    time.sleep(5)
    restart: "no"

  sglang:
    image: lmsysorg/sglang:latest-cu130
    container_name: sglang
    depends_on:
      model-download:
        condition: service_completed_successfully
    ports:
      - "30000:30000"
    volumes:
      - hf-cache:/root/.cache/huggingface
    environment:
      - HF_HUB_OFFLINE=1
    ipc: host
    command:
      - python3
      - -m
      - sglang.launch_server
      - --model-path
      - Qwen/Qwen3-0.6B
      - --host
      - 0.0.0.0
      - --port
      - "30000"
      - --context-length
      - "8192"
      - --mem-fraction-static
      - "0.75"
      - --reasoning-parser
      - qwen3
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: all
              capabilities: [gpu]
    restart: unless-stopped

  open-webui:
    image: ghcr.io/open-webui/open-webui:main
    container_name: open-webui
    depends_on:
      - sglang
    ports:
      - "3000:8080"
    environment:
      - OPENAI_API_BASE_URL=http://sglang:30000/v1
      - OPENAI_API_KEY=none
      - WEBUI_AUTH=false
    volumes:
      - open-webui:/app/backend/data
    restart: unless-stopped

volumes:
  hf-cache:
    name: hf-cache
  open-webui:
    name: open-webui

# WSL2 native install · SGLang — check the GPU first
nvidia-smi

# build tools (one-liner)
sudo apt update && sudo apt install -y build-essential python3-dev curl git

# install uv (one-liner), then reload the shell
curl -LsSf https://astral.sh/uv/install.sh | sh
source ~/.bashrc

# create and activate a python 3.12 venv
uv venv ~/sglang-env --python 3.12
source ~/sglang-env/bin/activate

# install sglang with prereleases (one-liner)
uv pip install --prerelease=allow sglang openai "huggingface_hub[hf_transfer]"

# each new shell: activate + use the hf mirror
source ~/sglang-env/bin/activate
export HF_ENDPOINT=https://hf-mirror.com

# serve (multi-line command — backslashes join it into one)
sglang serve Qwen/Qwen3-0.6B \
  --host 0.0.0.0 --port 30000 \
  --context-length 8192 \
  --mem-fraction-static 0.75 \
  --reasoning-parser qwen3

# 1. download and register the NVIDIA cuda keyring (one-liner wget)

# 2. install the keyring package
sudo dpkg -i cuda-keyring_1.1-1_all.deb

# 3. install cuda toolkit 13.0 (one-liner)
sudo apt update && sudo apt install -y cuda-toolkit-13-0

# 4. persist CUDA_HOME and reload (one-liner)
echo 'export CUDA_HOME=/usr/local/cuda-13.0' >> ~/.bashrc && source ~/.bashrc
